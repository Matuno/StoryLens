# Story Lens contract

Status: **ACTIVE / maintained, version 1.0.2.0** in `projects/active/StoryLens`. Owner: Matuno. Public source: https://github.com/Matuno/StoryLens. Historical verification sections retain their status at the time; the 2026-10-20 promotion record supersedes those incubator labels.

Registry, automation and report paths refer to the development workspace. The public repository builds independently; [CONTRIBUTING.md](CONTRIBUTING.md) provides standalone commands.

## Identity and purpose

- Internal name: `StoryLens`
- Owner: Matuno
- Purpose: Shows quest objective overlays and uncertain story-progress clues for visible players, with persistent last-seen points for manually tracked players and the full Free Company roster.

## Inputs and triggers

A manual name/home-world tracked list, explicitly added player target, or selected session-only observation. Framework samples of all valid spawned players exposed by the local object table, excluding the local player; quest/Level sheets, positions and public OnlineStatus. The user's 2026-10-15 instruction explicitly authorizes preemptive session-only observation of all visible players and persistent last-seen data only for tracked players.

## Outputs and persistence

/storylens opens Free Company, Follow player, Quest browser and Settings. The overview shows rough progress and last-observed times. Following a player anchors a path of up to three previous/five upcoming quests to their strongest recent observation or public-progress estimate. The always-visible candidate section lists every observed quest within the retained clue set, with recent/earlier counts, possible steps, supporting observation, UTC time and shared-quest count. Selecting a candidate explicitly centers its path and filters its world markers. Other quest cards preview details without moving that candidate's path. Click the selected candidate again, Clear quest or Close details to clear the explicit selection and restore all markers; following resumes only explicitly. Clear player removes all UI selections. Selection state is ephemeral and never deletes recorded evidence. Changing the detailed quest scrolls its evidence and summary into view.

Configuration schema 3 persists the tracked list, preferences, and tracked last-seen UTC time, territory/map/instance, world position and up to 128 clue references/timestamps. Session-only players never enter configuration. Adding a tracked player adopts their existing session evidence. New tracked snapshots checkpoint every 30 seconds, with immediate saves for explicit tracking/settings changes and flushes on logout/unload. Schemas 1 and 2 migrate without losing the list/preferences. Chain browsing adds no persisted player data and never asserts quest completion.

## Client-state and unload behavior

Pause reads/overlays and break observation continuity on logout, zoning, instance change, duty, PvP, GPose and local cutscenes. Logout retains in-memory session observations and flushes tracked data. Unload flushes tracked data, clears the ephemeral cache, and removes commands, framework/UI/context-menu events and both IPC gates. A single cancellable HTTP operation may run off-thread; unload cancels and awaits it before disposing HTTP resources. Native pointers are never retained. Saved clues never seed live actor/status continuity, so a reload cannot invent a fresh cutscene transition.

## Privacy and retention

All spawned player identities/positions and bounded clue sets may be retained in RAM for this running plugin session, as explicitly requested. Manual players and verified FC members may persist locally. The current user instruction authorizes automatically reading their public Lodestone profiles. Public character/FC Lodestone IDs, profile freshness and progression evidence are saved locally. No content/account IDs, telemetry, identity logs or identity/position export through IPC. Stopping manual tracking deletes the saved point unless the player is also an automatically tracked FC member; ordinary session-only observation continues. Clearing recorded data deletes that player's saved/session evidence; enabled observation can gather new data afterward. Pause stops collection. Session-only data is discarded on unload/game exit and can be evicted at the documented capacity limit. No historical location trail is written; tracked records are a single last-seen snapshot plus bounded quest clues.

## Explicit non-goals

No exact remote quest-state access or claim of completion. No remote invisible NPC recreation, gameplay automation, input synthesis, memory writes, hooks, arbitrary commands or network service. Only verified FC membership automatically enrolls session players in persistent tracking. No private-profile bypass, login cookies, external API service or cross-client sharing.

## Inference and data assumptions

- Catalog: all named quests with nonempty internal IDs; issuer locations plus all nonzero valid TODO Level references. Display numbering follows the objective list, starting with quest acceptance as step 1 and including text-only steps. World labels append step/total without distance; shared locations retain all applicable step numbers. Underlying TODO indices remain unchanged. Completion sequence is stored as metadata and is not presented as another player's current sequence.
- `Level.X/Y/Z`, `Territory` and `Map` supply world coordinates and scope. NPC labels resolve type-8 objects through `ENpcResident`. Story phasing never controls whether an overlay may be shown.
- MSQ browsing classification uses `JournalGenre.Icon == 61412`, checked against the installed data. This filter affects only the quest browser, not world markers or ambiguity calculations. World markers include all nearby quest types unless StorySelection.QuestId holds an explicitly selected quest; an inferred quest while following a player does not narrow them. Clearing or toggling off the quest immediately restores the full nearby set.
- Quest icon type comes from `Quest.EventIconType`: `NpcIconAvailable + 1` for icon ranges, otherwise its sole icon. Blue unlock rows are 8/10. Missing icon metadata falls back to the installed MSQ/normal type rows (3/1). No game quest icon asset is distributed with the plugin.
- Quest details lazily read the installed `quest/{low-16-bit quest ID / 100:000}/{Quest.Id}` text sheet. Exact `TEXT_{internal ID}_SEQ_00` and `_TODO_{index:00}` keys provide the summary and objective labels; unknown text falls back to numbered locations. Text-only steps remain visible. These are static quest instructions, not another player's current journal text.
- Objective highlights use the latest non-future evidence timestamp for that quest. A visible player matching those locations within the 20-minute evidence window supports **Possible now**; otherwise it is **Last match**, with current step unknown. Multiple matching steps or quests stay explicitly ambiguous. Earlier steps are never marked complete. Unlock-based minimum progress alone does not select a current objective.
- The cutscene online status is resolved by the English `OnlineStatus` label `Viewing Cutscene` from installed sheets. Missing/ambiguous status metadata fails plugin initialization; there is no guessed offset or raw native fallback.
- Samples occur every 250ms for all valid spawned players exposed by the object table, with no additional distance cutoff. A match is within 6 horizontal and 4 vertical yalms, in the local territory and map. Continuity additionally requires the same zone instance and actor ID, nondecreasing time and a gap at most 1 second. A cutscene-start clue requires a false-to-true edge and displacement at most 3 yalms. All observations are heuristic, including apparently unique catalog matches.
- Linger evidence requires 8 seconds of continuous proximity. Public ICharacter.StatusFlags.InCombat supplies another player's combat state; combat entry uses the same continuity/displacement checks as cutscene entry, and a first-seen combat flag is not an entry. No monster spawn, owner, remote dialogue event or quest trigger is inferred from it. Repeated samples do not accumulate votes. Within the recent/historical groups, evidence ranks cutscene entry, cutscene present, combat entry, linger/combat present (equal), then proximity. Saved clues use the same strength ordering, preserving the original enum values. Unattributed combat does not establish the FC overview's MSQ percentage.
- Saved/live clue merging ranks before deduplicating objective keys. A weak proximity sample after reload cannot erase a stronger recent saved clue; a new visit supersedes it after the 20-minute freshness window. Live continuity is still never restored from saved clues.
- A unique match means one quest in the full catalog match set, including side quests; it does not mean proof. The overlay's marker limit, filters and overlap suppression never determine this count. Private quest state, missing coordinates, repeat visits and unrelated events remain unresolved. Missing cutscene/combat transitions do not exclude NPC dialogue or skipped events.
- Numbered nonzero CUTSCENE script parameters flag a quest-wide cutscene reference. They do not map cutscenes to TODO steps; absence does not imply dialogue-only. NPC locations do not by themselves distinguish dialogue, cutscene or encounter triggers. Linked duties likewise remain quest-wide associations.
- Path cards show each associated duty's name immediately beneath the quest name, with ContentFinderCondition.ContentType.Icon from the installed sheets. Unnamed legacy solo encounters use ContentType row 7 (Quest Battles). Missing icon metadata uses a generic duty glyph. Relation details remain available on hover and in quest details.
- Cap: 32 manually tracked players plus up to 512 FC members, 4,096 session entries and 128 clues per player. Oldest untracked entries are evicted at capacity; tracked entries are protected. Clues do not expire after 20 minutes: that window gives recent observations ranking priority, then strength/time. A new visit after the window replaces the old clue for the same objective. Last-seen and clue timestamps remain distinct, and saved/absent observations are labelled explicitly. Invalid configuration fails initialization without rewriting. Save failures remain visible and retry after 30 seconds; a crash can lose the latest checkpoint interval.
- The overlay is an ImGui projection of managed positions, without depth/wall occlusion. It shows at most 32 candidate markers per frame within 150 yalms, suppresses nearby screen overlaps, and never edits native map markers, NPCs or quest state.
- Objective rows show the number followed by instructions, then coordinates and map/floor name. On an explicit map-icon click, public IGameGui.OpenMapWithMapLink opens the game map and sets its normal flag. MapLinkPayload uses the objective's territory/map IDs and raw X/Z scaled by 1,000 before integer conversion; its coordinate formatting applies that map's scale and offsets. Missing coordinates/map metadata provide no button, and a rejected map-open request shows an error. This user-requested map UI action adds no direct native access, movement, teleport or chat operation.
- Chain metadata includes all named quest records with nonempty internal IDs, even without coordinates. `Quest.PreviousQuest` provides predecessors; reversed edges provide successors. Traversal stays within MSQ or other quest kind, stops at three predecessors/five successors, and never arbitrarily chooses at a fork. Branches, alternate versions, missing data, ends and cycles are surfaced. Cross-kind prerequisite quests are listed separately. The view does not infer player completion from chain position.
- Duty associations use `Quest.InstanceContentUnlock`, `Quest.InstanceContent`, quest-linked `ContentFinderCondition.UnlockCriteria/UnlockCriteria2` with unlock type 1, and numbered `INSTANCEDUNGEON` / `QUESTBATTLE` script symbols. InstanceContent resolves to ContentFinderCondition; QuestBattle IDs at least 5000 resolve through InstanceContent, older IDs through QuestBattleResident.SoloDuty with a generic fallback for valid unnamed QuestBattle records. Duty names/types come from sheets, with a generic category for blank type labels. Duplicate associations merge their reference/unlock/prerequisite labels. Unknown symbols are not interpreted as duty IDs. Links may include optional/alternative requirements, retired versions or incomplete coverage; they are not assertions of entry/completion or exhaustive duty requirements.

## Free Company extension (2026-10-15)

The user explicitly requests automatic progress tracking for all members of their Free Company, public mount/minion/achievement checks, combat-level ceilings and location clues. This supersedes the earlier manually selected-only persistence and no-network scope.

- Schema 3 preserves manual players and last-seen points. FC records are separate from the 32-entry manual list and may contain up to 512 validated name/world/public-Lodestone-ID pairs. Configuration validation permits saved points only for that union. Newly enrolled FC members adopt existing session clues. A complete verified replacement roster removes departed members' saved points unless manually tracked; failed/partial roster reads preserve the previous roster. Switching local characters requires verifying the new roster before replacement. Debug mode defaults off.
- Native reads: `InfoProxyFreeCompanyMember.Instance()`, `FreeCompanyId`, matching `InfoProxyFreeCompany.Id/TotalMembers` (coverage diagnostics), inherited `EntryCount`, `CharData`, and each cached `CharacterData.NameString/HomeWorld/Location/State`. Guards require a pointer, a count in 1..200, and the local character's name/home-world in that cache before trusting the company. Copy immediately to managed values, without reading content/account IDs. Offline/disconnected entries do not supply locations. The live experiment confirmed the local cached Location equals public ClientState.TerritoryType. Cached locations are supporting evidence, not a fresh server observation; record time is the time this plugin first saw that cached value change. No request-data functions, list paging actions, signatures, hooks or memory writes.
- Complete membership comes from all public Lodestone `/freecompany/{id}/member/?page=N` pages, validated before atomic replacement. Native caches cover at most 200 members. - A single HttpClient connects only to `https://na.finalfantasyxiv.com`, using GET, no cookies and no redirects. Paths are constructed from validated numeric IDs and escaped search text. One outstanding request, at least 5 seconds between dispatches, 20-second request timeout, 4 MB response limit, one-second regex timeouts. Requests operate on managed strings only. The framework reads public InCombat and all three BoundByDuty conditions each 250ms scan. Section outcomes remain stored independently. Collection and saved evidence remain unchanged.
