## Other signals

- **Achievements:** the public character's Main Scenario category at `/achievement/category/76/` contains both completed and uncompleted entries. Only `data-achieved="1"` counts; checking for an achievement link alone would be wrong. Match owned IDs to the game's English achievement description and quest key. Private/missing pages are recorded as unavailable, not as zero progress. A live member's hidden achievements returned HTTP 403 with the correct character frame; this privacy response is handled separately from generic 403 blocks and 429 rate limits. The current observed page contains the complete category without pagination. A future paginated layout needs a parser update; missing achievements never lower the known floor. Official [achievement database](https://na.finalfantasyxiv.com/lodestone/playguide/db/achievement/).
- **Levels:** parse the complete DoW/DoM section of `/class_job/`, including unlearned placeholders; exclude DoH/DoL and Blue Mage. The maximum normal combat-job level supplies a ceiling before the first MSQ requiring a higher level. It never proves the person has reached that level's story. Stale snapshots and contradictory positive evidence are surfaced; a snapshot older than three days supplies no ceiling. Equipped job level, including the roster's displayed job, is not a maximum.
- **Current location:** visible players supply exact territory/map/instance/coordinate observations. The read-only cached native FC list additionally supplies territory IDs for some online members. These can be stale and are labelled cached. The Ocular is territory 844/map 547 in this game build; many MSQs share it. An entry there suggests ShB access, not a particular quest. Generic territory hints use the earliest catalog MSQ objective in that exact territory and remain weak hypotheses. Housing, teleports, revisits, New Game+, missing/retired objectives and shared names prevent treating this as completion proof.
- **Fine observations:** existing 6-yalm horizontal/4-yalm vertical matches, 8-second linger and consecutive cutscene-status transition checks remain available. An estimate uses unique MSQ matches of at least linger strength. Ambiguous objectives stay visible in the evidence list without arbitrarily picking one for the percentage.

## Acquisition and verification

The user's current request authorizes FC-wide local persistence and automatic public-profile reads. The official [FC member list](https://na.finalfantasyxiv.com/lodestone/freecompany/) is paginated; the native cache cannot establish complete membership. Every page is checked, duplicate/missing/repeated pages fail the batch, and only a complete roster containing the local character replaces the prior roster.

The collector dispatches at most one HTTPS GET per 5 seconds, one in flight, with no cookies, login, redirects or private-data bypass. Four pages per stale member means roughly 2.8 active hours for an initial 499-member scan. No published request-rate allowance was found in the official [Lodestone help](https://na.finalfantasyxiv.com/lodestone/help/) or [site information](https://na.finalfantasyxiv.com/lodestone/help/about_the_lodestone/) checked on 2026-10-15; `/robots.txt` returned 404. Five seconds is a conservative local pacing choice, not an official quota. HTTP errors now use a 10-minute minimum global backoff and honor longer Retry-After values. Already saved deadlines remain intact because older builds did not record the source of the delay. Combat and any of the three public duty flags pause new dispatches, processing and native FC polling; an in-flight response can finish buffering and waits for resume. A three-day character TTL and six-hour roster TTL, persisted section cursor and error backoff prevent repeated bulk scans. Section outcomes distinguish public evidence from unavailable data. Runtime diagnostics and IPC expose only aggregate counts and pause/pacing status.

Native assumptions were checked against the current SDK ClientStructs source and live, bounded read-only experiments: local entry present, company cache count 200, company total 503, matching proxy company IDs, and cached local Location equal to public ClientState.TerritoryType. No native layout is copied into the plugin. Live IPC checks prove loaded assembly identity and aggregate invariants; they do not prove a person's actual private quest progress.

Completion audit additionally compared the official FC profile's **Active Members: 499** with all ten roster pages (50 per page, 49 on the last): all 499 official entries are represented. The differing native cached total is displayed rather than treated as authoritative fresh membership. A bounded live check exercised the same estimate method used by the UI for collected profiles and validated abbreviated stage/percentage/status labels without exporting identities or per-player clues.

The faster-sweep follow-up passed 63 deterministic tests and clean work/release/staging/live builds. Exact-DLL live smoke confirmed the five-second interval and retained data. Its first subsequent class/job request received generic HTTP 403, distinct from a matching private-profile response; the collector backed off until 2026-10-15 15:49:23 UTC without losing evidence. The deadline was preserved. This verifies failure handling, not permission for or sustained acceptance of the faster rate. Combat/duty condition combinations are covered by deterministic tests; real in-game transitions have not been exercised.

## Lodestone scraper and API research (2026-10-15)

- **Lucky Bancho:** his [collection-method FAQ](https://luckybancho.ldblog.jp/archives/55033904.html) describes HTML-only collection of character, job, mount and minion pages, paced on one PC according to responses. It uses publicly accessible data without login. No published crawler source or documented developer API was found; his [GitHub account](https://github.com/LuckyBancho) lists only an unrelated image-trimming library. This is a search finding, not proof that no source exists elsewhere.
- **[NetStone](https://github.com/xivapi/NetStone):** a C#/.NET Lodestone parsing library covering characters and FCs. Its [client source](https://github.com/xivapi/NetStone/blob/master/NetStone/LodestoneClient.cs) fetches Lodestone HTML and includes class/job, collections and achievement operations. It is a candidate for parser reuse, not an independent data source or a way around Lodestone access restrictions.
- **[NetStone API](https://github.com/Tawmy/NetStone.Api):** a separate hosted/self-hostable REST service with cached character, class/job, mount, minion, achievement and FC/member endpoints. The public [v4 OpenAPI document](https://netstone.eorzea.online/swagger/v4/swagger.json) was reachable and reported service 4.4.2, with `maxAge`, cached fallbacks and OAuth security. The [SDK documentation](https://github.com/Tawmy/NetStone.Api.Sdk) specifies OAuth client credentials with signed JWT certificates via FFXIV ID. Authenticated character retrieval and access onboarding were not tested. The maintainer's [release notes](https://wiki.tawmy.net/books/netstone-api/page/release-notes) report continued updates and use of a NetStone fork.
- **[Nodestone](https://github.com/xivapi/nodestone)** provides a TypeScript parser that can run as a server; **[Godestone](https://github.com/xivapi/godestone)** is a Go scraper. Neither was installed or executed in this workspace.
- **XIVAPI:** its [migration guide](https://v2.xivapi.com/docs/migrate/) says the old Lodestone endpoints became effectively nonfunctional by late 2023 and are not planned for v2. Its [software guide](https://v2.xivapi.com/docs/software/) explains that centralized scraping was blocked and recommends the above scraping libraries instead. V2 game-sheet data does not supply live player profiles.

Recommendation: evaluate NetStone's parsers before replacing the current small parser; investigate authenticated NetStone API access if a shared cache is desired. Its API would add an external service and credential handling, and remains dependent on Lodestone availability. No API integration, new dependency, credential setup or transfer of the tracked roster to another service was performed for this research.

## Observation uncertainty and interaction types (2026-10-20)

The public [ICharacter API](https://dalamud.dev/api/Dalamud.Game.ClientState.Objects.Types/Interfaces/ICharacter/) exposes OnlineStatus and StatusFlags for visible characters. The installed framework source at f7d06f363955251991222363a7c008b8998b6565 maps StatusFlags.InCombat from that character's InCombat flag. Its Condition service instead wraps the single local Conditions.Instance(); it is not another player's dialogue/cutscene condition array. StoryLens now copies the public combat bit on the framework thread and records continuous combat entry separately from first-seen combat, using the existing coordinate and continuity checks. This is activity evidence, with no monster ownership or quest attribution.

The installed Quest sheet has TODO locations and completion sequences; QuestListenerParams has listener IDs, behavior values and actor spawn/despawn sequences. These describe quest data, not a remote player's current event. Inspection did not establish a reliable TODO-to-dialogue/cutscene/fight classifier. The implementation therefore does not guess one from an NPC coordinate or from an absent status change. Numbered CUTSCENE script parameters are displayed only as quest-wide references: In the Dark of the Tower (69913) contains CUTSCENE0/1/2 = 2616/2617/2618, but these parameters do not associate those scenes with specific TODO rows. Absence is not evidence of dialogue-only. Existing QUESTBATTLE/INSTANCEDUNGEON references remain quest-wide duty associations.

One known quest matching a cutscene-start observation is useful support, never irrefutable proof. The status does not identify its originating quest or scene, a remote quest journal is unavailable, and the catalog may omit event-only coordinates. A single drawn marker is weaker still: overlap suppression, explicit filtering and the 32-marker display cap can hide alternatives. Ambiguity counts use the full coordinate match set, including side quests, independently of rendering. Combat or a monster appearing nearby likewise cannot identify who initiated a quest encounter; no spawn detector or ownership claim was added.

The real catalog probe loaded all 5,373 named quests and 471 distinct linked duties. All 16 duty icon assets resolved from ContentType exist. It's Probably Pirates (66211) resolves Sastasha and dungeon icon 61801; legacy unnamed solo encounters use the installed Quest Battles category, row 7/icon 61805. Duty names/icons are rendered immediately beneath path quest names, with relationship labels on hover and in details. No game data or assets are bundled.
